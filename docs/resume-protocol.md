# 續傳協定擴充（第 1 版）

LocalSend v2 協定的本分支擴充：傳到一半斷線時，從接收端「確定寫進儲存裝置」的位置接著傳，不必整個檔案重來。
官方版 LocalSend 不認得這些欄位與端點，雙方都支援時才會使用，所以和官方版互傳時行為完全不變。

設計理由與取捨請見 [設計文件](superpowers/specs/2026-11-16-resumable-transfer-design.md)。
以下內容是給其他實作（例如日後的 `web-peer/`）參考的規格。

## 前提

- 只在 **HTTPS（雙向憑證）** 下使用。續傳以傳送端的**憑證指紋**辨識身分；未加密模式下對方自報的指紋可以偽造。
- 每個檔案都要有 `sha256`（傳送端「計算檢查碼」）。續傳完成的檔案**一律**驗證整檔 SHA-256，即使接收端關閉了「驗證檢查碼」。

## 能力協商

`POST /api/localsend/v2/prepare-upload`

請求本體多一個欄位：

```json
{ "info": { … }, "files": { … }, "resumeSupport": 1 }
```

接收端同意續傳時，回應多兩個欄位：

```json
{
  "sessionId": "…",
  "files": { "fileA": "tokenA", "fileB": "tokenB" },
  "resumeSupport": 1,
  "resumeOffsets": { "fileA": 52428800 }
}
```

- `resumeOffsets`：接收端已經持有的位元組數（來自之前中斷的傳輸）。只列出大於 0 的檔案；沒列出的從 0 開始。
- 回應沒有 `resumeSupport` 時，整個工作階段照官方行為處理，不得使用下面的參數與端點。

## 從指定位置上傳

`POST /api/localsend/v2/upload?sessionId=…&fileId=…&token=…&offset=N`

- 本體是檔案第 `N` 個位元組到結尾（長度 `size - N`）。`offset` 省略等於 0；為了相容官方版，`N` 為 0 時不送這個參數。
- `N` 必須等於接收端目前記錄的位置，否則回 **409**：

  ```json
  { "message": "Offset mismatch", "offset": 52428800 }
  ```

  傳送端直接改用回應裡的 `offset` 重送即可。
- 續傳後整檔 SHA-256 不符時回 **422**，接收端把位置歸零，傳送端從 0 重傳（同一個檔案最多 3 次）。

## 查詢已收位置

`POST /api/localsend/v2/upload-offset?sessionId=…&fileId=…&token=…` → `200 {"offset": N}`

- 如果這個檔案還有一個舊的上傳請求在進行（接收端還沒發現連線已斷），接收端會先中斷它，等它把已收內容寫進儲存裝置之後才回應。所以是 POST。
- 檔案已完成時，`offset` 等於檔案大小；傳送端應直接當作完成（可能只是最後的回應遺失）。
- 工作階段已結束、憑證不符、不是可續傳的工作階段、或檔案已失敗時回 **403**。
- 舊上傳 10 秒內沒有收尾時回 **503**，傳送端稍後再查即可。

## 身分與工作階段

- 可續傳的工作階段以傳送端**憑證指紋**驗證 `upload`、`upload-offset`、`cancel`，**不比對來源 IP**，所以傳送端換了 IP 也能續傳。
- 上傳中斷時，檔案改為「中斷」狀態並記錄已確定的位置，**工作階段不結束**。
- 沒有任何上傳在進行、持續 **5 分鐘**後，工作階段結束，其他裝置才能開始新的傳輸（這段期間其他裝置會收到 409 忙碌）。
- 同一個傳送端（憑證相同）帶 `resumeSupport` 送來新的 prepare-upload，而且包含舊工作階段裡還沒完成的同一個檔案（SHA-256 與大小相同）時，舊的工作階段結束；結束前會先中斷並等候它進行中的上傳收尾。其他請求照舊收到 409。
- 可續傳的工作階段被任一方取消時，進行中的上傳一併中斷。
- 沒有 `sha256` 的檔案即使在可續傳的工作階段中也不續傳。
- 接收端的應用程式必須能把同一個檔案寫回同一個位置，才可以宣告支援（本倉庫的 CLI 每次都取新檔名，所以不宣告）。

## 傳送端的重連規則（本分支 App 的做法）

- 連線層級的錯誤（逾時、連線被重設、本體送到一半失敗，以及 500、503）：依序等 1、2、4、8、15、30 秒，之後每 30 秒一次，每次先查詢 `upload-offset`，再從那裡上傳。
- 沒有進展超過 **5 分鐘**才放棄；只要查到的位置比上次斷線時更後面，就重新計時。
- 403／404：工作階段已不在，停止重試。使用者重新傳送時，接收端會在 `resumeOffsets` 給出之前收到的位置。

## 接收端的半成品（本分支 App 的做法）

- 可續傳的檔案先寫進隱藏的 `.<檔名>.<登記編號>.lspart`，驗證通過後才改成不衝突的正式檔名。同一個半成品同時只允許一個寫入者，同一筆半成品也只配給一個檔案。
  - Android 儲存空間存取框架（SAF）只有系統儲存空間會這樣做；其他文件提供者一開始就用正式檔名。
  - 存相簿的檔案放在快取資料夾 `resume/<id>/` 底下，完成後照常搬進相簿。
- 半成品記錄在應用程式支援目錄的 `resume/partials.json`，以「傳送端憑證指紋 + SHA-256 + 大小」比對。
- 每寫入 16 MiB 確定一次位置（只在可續傳的工作階段）；超過 **7 天**沒有更新的半成品會被刪除。
- 使用者在確認畫面改了存放資料夾或「存相簿」設定時，該檔案從 0 開始。
